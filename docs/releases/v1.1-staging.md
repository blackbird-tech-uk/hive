## Required gates before any production deployment

### 1. Establish safe staging
- Identify the actual API endpoint used by the release preview **without publishing credentials**.
- Confirm that endpoint belongs to a non-production API with a distinct non-production PostgreSQL database. Do not reuse production database credentials or data.
- Ensure the staging API runs the release branch commit and its migration.
- If isolation cannot be demonstrated, **stop**; do not sign in or run write tests on the preview.

### 2. Authenticated smoke tests on isolated staging
- Sign in with a staging-only account; verify dashboard and sign-out.
- Check organisation A cannot read or modify organisation B events, map areas or assignments.
- Create an event and a polygon map area; refresh and confirm persistence; update and delete the area.
- Assign a test scanner to an area, verify persistence and visibility on the fleet map; reject cross-organisation assignment.
- Verify existing scanner listings and assignment behaviour still work.
- Check mobile layout and console/network errors; record exact API responses for failures.

### 3. Production readiness
- Record current production Alembic revision and count events missing organisation ownership.
- Confirm migration's backfill assumptions are valid for the live data.
- Verify a restorable production database backup and a recovery owner.
- Review migration `f31a6b8c02e4`: downgrade drops map areas and related columns, so prefer app rollback with DB migration retained; do not blindly downgrade.
- Review the tested release SHA, all CI results, and the staging evidence; request explicit release approval.

### 4. Controlled rollout
- Schedule an appropriate maintenance window; take a fresh backup.
- Apply the reviewed database migration only after the above gates pass.
- Deploy the compatible API, verify health and tenant isolation, then deploy/promote the web app.
- Smoke-test the live site and monitor errors. Stop and follow the recovery plan if checks fail.

## Change scope
- Web: fleet-map pins, zones, styles and API integration.
- API: organisation-scoped events, map-area CRUD and scanner assignment-to-area.
- Database: PostgreSQL migration `f31a6b8c02e4`.
- Android Agent: **not included** in this release.

This checklist distinguishes confirmed evidence from pending tests. A READY Vercel preview alone is not authorization to merge or deploy.
