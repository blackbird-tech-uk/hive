# HIVE V1.1 — release preparation

**Status:** Preparing; **not deployed**. Branch created from `main` to avoid including unfinished Android Agent work from PR #42.

## Candidate release changes (not yet cherry-picked)

- Fleet map pins, zones and map-area UI
- Organisation-scoped event ownership and map-area API
- Scanner assignments associated with event areas
- Organisation isolation and access-control tests

## Excluded

- Android Agent 0.1.1, APK signing and enrolment changes
- Unfinished automatic scanner-token renewal
- Any unreviewed change from the 106-commit feature branch

## Required checks before production

1. Identify a minimal coherent web/API patch set; review API, web and migration dependencies.
2. Verify Alembic upgrade/downgrade against isolated PostgreSQL with representative existing event data.
3. Review unowned events when more than one organisation exists; ensure no unintended cross-tenant access.
4. Verify a recent restorable production database backup and current migration revision.
5. Run API/Web CI and smoke tests on the exact release commit.
6. Confirm Railway/Vercel deployment access and application rollback plan.
7. Deploy with explicit go/no-go approval; validate production and record deployed commit IDs.

## Change notes for the eventual release

- **Web:** map pins and polygon areas, fleet map presentation.
- **API:** event ownership, area routes, area assignment and tenant access checks.
- **Database:** nullable event organisation reference, new map areas table, optional assignment area reference.
- **Caution:** migration downgrade deletes map areas and added columns; do not rely on a destructive downgrade as a routine rollback.

The above describes candidate changes, **not completed deployment**.
